# CREAMS - Modules and Requirements Documentation
# Community-based REhAbilitation Management System
# Last Updated: August 15, 2025

===============================================================================
                           SYSTEM OVERVIEW
===============================================================================

CREAMS is a comprehensive rehabilitation management system built for IIUM PD-CARE
using Laravel 10.x framework. The system manages community-based rehabilitation 
services with role-based access control, comprehensive activity tracking, and 
multi-centre operations.

TECH STACK:
- Backend: Laravel 10.x (PHP 8.1+)
- Frontend: Blade templates, Bootstrap 5, jQuery
- Database: MySQL 8.0+
- Authentication: Session-based with role-based access control
- Architecture: Multi-tenant with centre-based data isolation

===============================================================================
                        USER ROLES & PERMISSIONS
===============================================================================

1. ADMIN - Full system access, all modules
2. SUPERVISOR - Team oversight, centre management, reporting
3. TEACHER - Activity management, trainee instruction, attendance
4. AJK - Facility management, asset management, administrative tasks
5. TRAINEE - Limited access to personal data and progress
6. PARENT - View child's progress and receive notifications
7. PUBLIC - Access to home, contact, and volunteer pages

===============================================================================
                     SESSION AUTOMATION REQUIREMENTS
===============================================================================

AUTOMATED SESSION STATUS MANAGEMENT:
-----------------------------------------------

The system requires automated session status updates based on date and time:

STATUS WORKFLOW:
1. SCHEDULED - Future sessions or current day before start time
2. ONGOING - Current day sessions between start and end time  
3. COMPLETED - Past sessions or current day after end time
4. CANCELLED - Manually cancelled sessions

AUTOMATION TRIGGERS:
- Hourly automated checks (recommended)
- Manual refresh button on dashboard
- System startup checks
- User login triggers

IMPLEMENTATION:
- Script: automate_session_status.php (created)
- Can be run via cron job every hour
- Can be triggered on dashboard refresh
- Integrates with existing session management

ATTENDANCE AUTOMATION:
- Every completed session MUST have attendance records
- Auto-generate attendance for sessions with enrollments
- Session-based tracking (not daily attendance)
- Real-time attendance coverage monitoring

## AUTHENTICATION SYSTEM (CRITICAL - NOT LARAVEL DEFAULT)
- Uses CUSTOM session-based authentication via MultipleUserGuard.php
- Session structure: 'id', 'role', 'name', 'centre_id', 'email', 'login_time'
- Role hierarchy: admin > supervisor > teacher > ajk
- Centre-based data isolation enforced at query level
- Login redirects based on role to specific dashboards

### AUTHENTICATION SOURCE CODE:
```php
// app/Extensions/MultipleUserGuard.php
class MultipleUserGuard extends SessionGuard
{
    public function user()
    {
        if ($this->user !== null) {
            return $this->user;
        }

        // If we have session ID, use it to fetch the user
        if (Session::has('id') && Session::has('role')) {
            $id = Session::get('id');
            $role = Session::get('role');
            
            switch ($role) {
                case 'admin':
                    $model = \App\Models\Admin::class;
                    break;
                case 'supervisor':
                    $model = \App\Models\Supervisor::class;
                    break;
                case 'teacher':
                    $model = \App\Models\Teacher::class;
                    break;
                case 'ajk':
                    $model = \App\Models\AJK::class;
                    break;
                default:
                    return null;
            }
            
            $this->user = $model::find($id);
            return $this->user;
        }
        
        return null;
    }
}
```

```php
// Activity.php - Core relationships
class Activity extends Model
{
    // Get all enrollments for this activity
    public function enrollments()
    {
        return $this->hasMany(ActivityEnrollment::class);
    }

    // Get only active enrollments
    public function activeEnrollments()
    {
        return $this->hasMany(ActivityEnrollment::class)
            ->where('enrollment_status', 'enrolled');
    }

    // Get enrolled trainees via pivot
    public function participants()
    {
        return $this->belongsToMany(Trainee::class, 'activity_enrollments', 'activity_id', 'trainee_id')
                    ->wherePivot('enrollment_status', 'enrolled')
                    ->withPivot(['enrollment_date', 'enrollment_status', 'progress_percentage', 'attendance_count'])
                    ->withTimestamps();
    }

    // Get upcoming sessions
    public function upcomingSessions()
    {
        return $this->hasMany(ActivitySession::class)
            ->where('session_date', '>=', now()->toDateString())
            ->where('status', 'scheduled')
            ->orderBy('session_date')
            ->orderBy('start_time');
    }
}
```

## WHAT IS CREAMS?
CREAMS is a comprehensive web-based management platform for Malaysia's rehabilitation center network. It manages:
- Rehabilitation services and programs
- Educational activities and sessions
- Trainee progress tracking
- Staff coordination and scheduling
- Asset and resource management
- Letter generation and documentation
- Multi-centre operations with data isolation

## USER ROLES & PERMISSIONS

**ADMIN (System-wide access)**
- All centres and functions
- User management (CRUD operations)
- System configuration and monitoring
- Activity management across centres
- Comprehensive reporting and analytics

**SUPERVISOR (Centre-level management)**
- Own centre data only
- Staff coordination within centre
- Activity oversight and session management
- Trainee management and progress tracking
- Centre-specific reports and letters

**TEACHER (Operational level)**
- Session management and attendance marking
- Assigned activity access
- Trainee progress updates
- Personal schedule management
- Limited activity creation (with approval)

**AJK (Committee member - limited)**
- View-only access to centre data
- Basic reporting capabilities
- No creation or editing permissions

## CENTRE MULTI-TENANCY
- Each centre operates independently
- Shared codebase, isolated data
- centre_id filtering on all major queries
- Admin role can access cross-centre data
- Session-based centre assignment

```php
// Standard Controller Error Handling Pattern
public function someMethod(Request $request)
{
    try {
        // Authentication check
        if (!session()->has('id')) {
            return redirect()->route('login');
        }

        // Role validation
        if (!in_array(session('role'), ['admin', 'supervisor'])) {
            abort(403, 'Unauthorized access');
        }

        // Centre filtering for non-admin
        $query = ModelName::query();
        if (session('role') !== 'admin') {
            $query->where('centre_id', session('centre_id'));
        }

        // Business logic here
        $result = $query->get();

        // Log success
        Log::info('Operation completed successfully', [
            'user_id' => session('id'),
            'action' => 'operation_name',
            'count' => $result->count()
        ]);

        return redirect()->back()->with('success', 'Operation completed successfully');

    } catch (\Illuminate\Validation\ValidationException $e) {
        return redirect()->back()
            ->withErrors($e->validator)
            ->withInput();
            
    } catch (\Exception $e) {
        Log::error('Error in operation: ' . $e->getMessage(), [
            'user_id' => session('id'),
            'trace' => $e->getTraceAsString()
        ]);
        
        return redirect()->back()
            ->with('error', 'An error occurred. Please try again.')
            ->withInput();
    }
}
```

## Task B1-T3: Remediate hardcoded passwords in server-init.sh

| Field | Value |
|-------|-------|
| **Task ID** | B1-T3 |
| **Priority** | P0 |
| **Source Evidence** | `CRITICAL_FINDINGS_REGISTER.md` CF-03 |
| **Finding Reference** | CF-03 — Hardcoded database passwords in deploy script (ProdPassword123!, StagingPassword123!, DevPassword123!) |
| **Problem Statement** | `scripts/server-init.sh` (261 lines) creates 3 MySQL users with hardcoded passwords, grants full privileges, and writes `.env` files containing these credentials. Unknown whether script was ever executed on a live Lightsail server. |
| **Affected Files** | `scripts/server-init.sh` |
| **Affected Components** | Lightsail MySQL users (prod, staging, dev), `.env.production` on server |
| **Dependencies** | Requires access to Lightsail server to verify deployment history. |
| **Execution Preconditions** | [ ] SSH access to Lightsail server (if deployed). [ ] MySQL root access on Lightsail (if deployed). |
| **Verification Steps** | 1. Check if server-init.sh was ever deployed: `[ -f /path/to/server-init.sh ]` on Lightsail. 2. If deployed: list MySQL users — `SELECT user, host FROM mysql.user WHERE user IN ('creams_prod', 'creams_staging', 'creams_dev');`. 3. If users exist with hardcoded passwords: ROTATE IMMEDIATELY — `ALTER USER 'creams_prod'@'localhost' IDENTIFIED BY 'new-secure-password';` for all 3. 4. Update `.env.production` on server with new password. 5. Update `scripts/server-init.sh` locally: replace hardcoded passwords with `"${PROD_DB_PASSWORD}"`, `"${STAGING_DB_PASSWORD}"`, `"${DEV_DB_PASSWORD}"` environment variable references. 6. Add comment to script: "# Set these env vars before running: PROD_DB_PASSWORD, STAGING_DB_PASSWORD, DEV_DB_PASSWORD". 7. If NOT deployed: only update the script locally (step 5-6). |
| **Rollback Strategy** | Before rotating passwords: dump current `.env` files on server. If rotation breaks connectivity, restore old `.env` and old MySQL passwords, then debug. |
| **Completion Criteria** | [ ] Deployment history confirmed (deployed or not). [ ] If deployed: all 3 MySQL passwords rotated. [ ] `scripts/server-init.sh` no longer contains hardcoded passwords — uses env vars. [ ] `.env` files on server updated if applicable. |
| **Estimated Effort** | 30 minutes (not deployed) / 1 hour (deployed — includes rotation + verification) |
| **Risk of Change** | MEDIUM if deployed — password rotation may temporarily break DB connectivity. Perform during maintenance window. Verify app connectivity after rotation. |
| **Notes** | This is the same script that blocked SSL certbot (failed approach #7). When updating the script, also fix the certbot command from `--apache` to `--nginx`. |

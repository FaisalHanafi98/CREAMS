EXECUTIVE SUMMARY
============================================================================

The CREAMS database architecture represents a comprehensive, normalized 
relational database designed specifically for rehabilitation center 
management in Malaysia. The system supports multi-center operations 
with role-based access control, complete audit trails, and scalable 
data structures optimized for community-based rehabilitation services.

KEY DESIGN PRINCIPLES:
- Multi-tenant architecture with center-based data isolation
- Role-based access control (Admin, Supervisor, Teacher, AJK)
- Comprehensive audit logging and data integrity
- Flexible activity and session management
- Scalable asset and resource tracking
- Integrated communication and letter generation systems

============================================================================
COLUMN NAMING CONVENTIONS & STANDARDS
============================================================================

The CREAMS database follows strict naming conventions to ensure consistency,
maintainability, and clarity across all tables and relationships:

1. PRIMARY KEYS:
   - Format: {table_name}_id (e.g., user_id, trainee_id, activity_id)
   - Type: INT AUTO_INCREMENT for most tables
   - Special: centres table uses centre_id VARCHAR(10) for Malaysian centre codes

2. FOREIGN KEYS:
   - Format: {referenced_table}_id (e.g., centre_id, user_id, category_id)
   - Maintains referential integrity with proper constraints
   - Cascade rules defined for data consistency

3. COLUMN PREFIXES:
   - trainee_*: All trainee-specific fields (trainee_first_name, trainee_email)
   - centre_*: All centre-specific fields (centre_name, centre_address)
   - activity_*: All activity-specific fields (activity_name, activity_description)
   - guardian_*: Guardian/parent information fields
   - emergency_*: Emergency contact information fields

4. TIMESTAMP FIELDS:
   - created_at, updated_at: Standard Laravel timestamps (TIMESTAMP)
   - date_of_birth, admission_date: Date fields (DATE)
   - session_date, attendance_date: Activity-specific dates (DATE)
   - last_accessed_at: User activity tracking (TIMESTAMP)

5. STATUS & ENUM FIELDS:
   - status: Generic status field (active, inactive, pending, etc.)
   - role: User roles (admin, supervisor, teacher, ajk)
   - gender: User/trainee gender (Male, Female)
   - attendance_status: Attendance tracking (present, absent, late, excused)

6. TEXT & CONTENT FIELDS:
   - *_description: Detailed descriptions (TEXT)
   - *_notes: Additional notes or comments (TEXT)
   - *_content: Rich content fields (LONGTEXT)
   - *_summary: Brief summaries (VARCHAR)

7. BOOLEAN FIELDS:
   - is_*: Boolean flags (is_active, is_completed, is_verified)
   - has_*: Possession indicators (has_consent, has_documents)
   - can_*: Permission indicators (can_edit, can_view)

8. MALAYSIAN-SPECIFIC FIELDS:
   - ic_number: Malaysian identification number (VARCHAR(15))
   - phone: Malaysian phone format (+60X-XXX-XXXX)
   - centre_id: Malaysian centre codes (01, 02, 03, 04)
   - iium_id: IIUM-style staff identification
